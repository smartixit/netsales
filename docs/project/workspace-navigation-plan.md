# تنفيذ العضويات والشركاء والتنقل في مساحتي عمل NetSales

**نطاق التنفيذ:** M2 وM3 وM4.  
**الاستثناء الصريح:** M1 (جرد الحوكمة الشامل) مستثناة ولا يُدّعى اكتمالها.  
**الحالة:** التنفيذ الأساسي مدمج في المستودعين؛ إغلاق مراجعة التكامل النهائي مرتبط باجتياز PR #89 على HEAD واحد.

## القرار المعتمد للتنقل

- مساحة الشبكة: الرئيسية، الطلبات، نقاط البيع، الملف الشخصي.
- مساحة نقطة البيع: الرئيسية، الطلبات، فواتيري، الملف الشخصي.
- أربعة عناصر بالضبط في شريط الهاتف؛ لا يوجد تبويب «المزيد».
- زر الإجراء العائم مستقل عن التبويبات: إصدار فاتورة بيع للشبكة، وطلب توريد لنقطة البيع.
- الأفاتار يفتح الملف الشخصي، وزر AppBar الآخر هو `CustomThemeToggleButton`.
- على الهاتف تُنظم الوجهات الثانوية في مجموعات مهام؛ وعلى الشاشات الواسعة يُستخدم التنقل الجانبي المتكيف.
- تبقى صلاحيات الوصول الفعلية والتحقق من نطاق المستأجر في Laravel؛ إخفاء الوجهة في Flutter ليس بديلاً عن الحماية الخادمية.

## العضويات والشركاء

- توحيد تدفقات عضويات Network وPOS في طبقات data/domain/presentation مع GetX وUseCases.
- دعم cursor pagination والبحث والتصفية على الخادم، مع حماية النتائج من الاستجابات القديمة عند تبديل البحث أو الحالة أو مساحة العمل.
- إرجاع ملخص إحصائي شامل للنطاق، لا مجرد أعداد الصفحة الحالية.
- توحيد مورد العضوية وحالاتها، مع إبقاء سجل العضوية منفصلاً عن بيانات المستخدم والدور.
- نقل تنسيق حوارات العضويات والشركاء إلى Presentation Coordinators، وإبقاء Widgets للعرض واستقبال callbacks.
- الحفاظ على فحوص الصلاحيات وملكية المستأجر وقواعد إسناد الأدوار في الخدمات والـ middleware القائمة.
- لا تغييرات في migrations أو التدفقات المالية ضمن هذا النطاق.

## الملف الشخصي ومساحات العمل

- ملف شخصي للقراءة فقط يعتمد عقد `GET /auth/me` الحالي، ويعرض بيانات الحساب والأمان والعضويات منفصلة.
- لا تُستخدم APIs إدارية لتعديل بيانات المستخدم الذاتية.
- شريط تنقل الهاتف ثابت بأربعة عناصر، مع تخطيط متكيف للأجهزة اللوحية وسطح المكتب.
- لا تُعرض وجهة على أنها عاملة دون شاشة ومسار وحارس واختبار مناسب.

## فجوات مؤجلة خارج نطاق هذه المرحلة

تظل أي مسارات لا تملك شاشة فعلية وعقد API وحارساً واختبارات خارج التنقل المرئي. لا تُعاد إضافة وجهات غير مكتملة لمجرد وجود route constants. كشوف المحافظ وسجل الديون وأي تدفقات تسديد مستقلة تحتاج مراحلها وعقودها الخاصة.

## قواعد التنفيذ

- GetX وClean Architecture وفق حوكمة المستودع.
- Controllers تدير حالة العرض وتفوض العمليات إلى UseCases؛ الشاشات للتجميع وWidgets للعرض.
- إعادة استخدام `lib/core` و`lib/widgets` ومكونات Design System الموجودة.
- لا منطق أعمال أو صلاحيات أو حسابات مالية داخل الواجهات.
- لا دمج قبل مراجعة diff واجتياز الاختبارات على SHA واحد.
